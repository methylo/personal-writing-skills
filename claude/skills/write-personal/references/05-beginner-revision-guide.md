# 초보자 수정 도움과 단계별 적용

원고를 완성하는 일과 고치는 방법을 이해하는 일을 함께 돕는다. 연습은 선택이며 다음 단계의 필수 통과 조건이 아니다. 4단계에서는 아래 도움 내용을 가장 중요한 수정안의 이유에 통합하고 별도 절로 반복하지 않는다. 아래 사례는 자세한 설명을 요청받았을 때의 형식 견본이다. 실제 글의 다른 문제로 바꿔 적용한다.

## 단계별 도움

| 단계 | 설명할 내용 | 사용자가 할 수 있는 일 |
| --- | --- | --- |
| 1 설계 | 실제 메모에서 장면·행동·생각을 구분하고, 주장을 받치는 재료와 빈 곳을 설명 | 기억나는 실제 장면이나 행동 1~2문장 추가 |
| 2 구성 | 각 문단의 역할, 추천 순서가 해당 독자에게 적합한 이유를 설명 | 강조할 장면·생각과 구성 선택 |
| 3 초안 | 잘된 부분 1개, 가장 중요한 수정 요령 최대 1개를 실제 문장으로 설명. 자체 점검으로 해결할 문제는 먼저 해결 | 문장 하나를 직접 고치거나 수정안 제안 요청 |
| 4 검토 | 정한 독자가 막히는 지점과 편집자의 수정 방법 연결. 정본 항목은 쉬운 뜻으로 풀어 설명 | 수정안을 고르거나 자기 문장으로 고쳐 보내기 |
| 5 반영 | 전후 차이와 좋아진 이유, 유지한 원래 뜻·말투를 설명. 주변 문장과 글자 수 점검 | 수정된 뜻이 맞는지 확인하거나 일부 되돌리기 |
| 6 최종 점검 | 남은 필수 수정과 선택 개선 구분. 승인된 수정에서 다음 글에 쓸 기준 하나를 제안 | 최종 확정 또는 필요한 부분만 보완 |

## 반복 문장을 고치는 도움 예

```text
수정 도움: 같은 생각을 두 번 설명한 부분 줄이기
보존할 문장: “읽을 마음은 처음부터 있었다.” — 이 글의 중심 생각을 드러냅니다.
고칠 부분: 뒤에서 다시 나온 “읽고 싶다는 생각은 이미 있었다.”
이유: 앞 문장과 같은 뜻이라 독자가 새로운 내용을 만나지 못합니다.
방법과 예시: 뒤 문장을 삭제하고 앞뒤가 이어지는지 읽어봅니다. 이어지면 삭제한 상태로 둡니다.
직접 해볼 일: 뒤 문장을 지운 문단을 보내 주세요. 연결이 자연스러운지 살펴드리겠습니다.
간편한 진행: “반복 문장 삭제안을 반영해줘”라고 요청해도 됩니다.
적용한 정본: 2-5 같은 뜻 반복 — 같은 판단을 거듭 설명하지 않기.
```

수정 예시로 새로운 행동·감정·효과를 만들어 넣지 않는다. 삭제로 분량이 줄면 그 사실을 알리고, 이미 있는 다른 재료를 쓰거나 필요한 실제 경험을 질문한다.

## 사용자가 직접 고친 문장을 보냈을 때

1. 이전 문장과 이번 문장을 대조한다. 원문이 없으면 비교에 필요한 해당 문장만 요청한다.
2. 원래 뜻과 주장 강도의 보존 여부를 확인한다. 뜻이 달라졌다면 의도한 변경인지 질문한다.
3. 더 좋아진 점을 독자의 읽기 경험과 연결해 한 문장으로 설명한다.
4. 남은 문제가 있으면 가장 중요한 한 가지에만 방법과 예시를 제시한다. 없으면 추가 수정 과제를 만들지 않는다.
5. 사용자가 수정·반영을 요청한 범위 안에서 처리하고 현재 작업 단계는 유지한다. 직접 연습을 했다는 이유로 처음부터 다시 진행하지 않는다.

## 품질 점검 적용 사례

- 초안에서 마지막 문단이 여러 문장이면 기본 칼럼의 한 문장 정리 조건을 3단계에서 확인한다. 6단계까지 미루지 않는다.
- 수정안이 앞 문장과 같은 내용을 만들면 승인받기 전에 해당 문장까지 함께 대조해 수정 범위를 정한다.
- 초안이 반복 없이 기본 분량에 못 미치면 “분량을 더 늘리겠습니다”라고 해설을 추가하지 않는다. 현재 길이와 부족한 실제 재료를 알린다.
- 정본 4 자기 표현 방식이 비어 있으면 그 예시를 필자의 말투로 적용하지 않는다. 실제로 쓴 문장 한두 개를 받는 것은 선택 보완으로 제안한다.
- 글자 수를 도구로 계산하지 않았으면 정확한 수치로 검증했다고 단정하지 않는다. 표기는 정본 목록과 대조하고, 확실하지 않은 말만 확인 필요로 남긴다.
