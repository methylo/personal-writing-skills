# 나만의 글쓰기

호출 이름: `나만의 글쓰기`와 `write-personal`을 같은 스킬 이름으로 인식한다. 예: “write-personal 스킬로 아래 메모를 글로 작성해줘.” 영문 호출에도 동일한 단계·정본·독자·분량 기준을 적용하며, 호출 이름만으로 출력 언어를 바꾸지 않는다.

경험·주장·최종 선택은 필자의 것이다. 요청한 단계만 진행하고 실제로 수행한 작업과 남은 결정을 구분한다.

## 기본값과 필자 보존

| 항목 | 기본값 |
| --- | --- |
| 매체·유형 | 대학교 신문·칼럼 |
| 독자 | 20대 대학생 |
| 본문 | 공백 포함 900~1,000자, 제목·안내·줄바꿈 제외 |
| 흐름 | 제목(주장 한 줄) → 도입 장면 → 경험·근거 → 독자에게 건넬 질문 또는 기준 → 정리 한 문장 |

- 현재 사용자의 매체·유형·독자·분량·구조 요청이 기본값보다 우선한다. 변경값은 이번 글의 설계 시트에만 적용한다. 새 글은 기본값으로 시작하되 이전 설정을 이어 쓰라는 요청은 따른다. 스킬 기본값을 바꾸라는 명시적 요청 없이 영구 변경하지 않는다.
- 메모에 없는 사실·수치·사건·감정·연구·효과·필자의 판단을 만들지 않는다. 승인된 주장·해석·고유명사·판단 강도를 보존한다. 불확실한 경험을 단정으로 바꾸지 않는다.
- 외부 자료는 사용자가 준 것만 쓰는 것이 기본이다. 경험 범위의 글에 외부 연구를 의무로 요구하지 않는다. 일반화나 효과 주장이 필요하면 근거 요청 또는 주장 범위 축소를 제안한다. 확인하지 못한 내용은 `확인 필요`로 표시한다.
- 다른 사람의 사적 정보는 삭제·익명화를 제안한다. 필자의 사적 정보도 필요한 범위만 쓴다. 과제 규정이나 사실 확인을 사용자가 했다고 임의로 쓰지 않는다.

## 필요한 자료만 읽기

- 이미 읽었고 현재 대화에서 내용이 유효한 이 스킬·정본·참고 파일은 재사용한다. 단계가 바뀌었다는 이유만으로 다시 읽거나 전체 폴더를 검색하지 않는다. 변경 통지, 내용 누락, 새 대화일 때 필요한 파일만 다시 읽는다. 읽지 않은 자료를 읽었다고 하지 않는다.
- 처음에는 이 파일만 읽어 단계를 판단한다. 아래 참고 파일은 설명이나 형식이 실제로 필요한 때만 해당 절을 읽는다. 모든 파일을 일괄 로딩하거나 매 단계 견본 전체를 읽지 않는다.
- 필요한 서로 독립적인 자료는 가능한 한 한 번에 읽는다. 이미 정한 독자·주장·제목·구성·최신 원고·수정 승인·보류를 재질문하지 않는다.
- 기본 작업은 현재 메모·정본으로 진행한다. 추가 검색·새 페르소나 여러 명·별도 에이전트·추가 평가 루프를 자동 실행하지 않는다. 사용자 요청이나 실제 근거 확인이 필요한 경우에만 범위를 넓힌다.

## 정본 확인·적용·설명

1. 3단계 초안 전에 `name: write-standard`인 「내 글 정본」의 현재 SKILL.md를 실제로 읽는다. 4~6단계로 바로 시작해도 최초 작업 전에 읽는다. 사용 가능한 스킬 목록에서 `write-standard`를 찾아 그 SKILL.md를 읽고, 확인한 위치는 같은 대화에서 재사용한다. 목록에 없으면 정본 미확인으로 처리한다(아래 5번).
2. 이미 읽은 정본은 4~6단계에서도 재사용한다. 기준과 원고를 대조하는 일은 매 단계 하되 파일을 매번 다시 불러오지 않는다. 정본 변경을 알리거나 내용이 누락되면 다시 읽는다.
3. 정본 우선순위는 6 내 기준 → 4 자기 표현 방식 → 1~3 기본 기준이다. 빈칸·괄호 속 예시는 필자의 취향으로 적용하지 않는다. 사용자의 명시적 요청을 우선하며 단계·분량은 메인 스킬이 관리한다.
4. 1~2단계 첫 안내는 “초안부터 ‘내 글 정본’을 읽어 적용하겠습니다.” 읽은 직후에는 “정본을 확인했습니다. [실제 기준 1~2개]를 적용하겠습니다.” 이후에는 “앞서 확인한 정본 기준으로 [이번 작업]하겠습니다.”라고 한 문장만 알린다. 진행 메시지에서 말했다면 답변 앞에 반복하지 않는다.
5. 4단계는 수정안의 이유에 실제 정본 항목을 넣고 별도 적용 목록을 반복하지 않는다. 3·5·6단계는 결과의 정본 적용 설명을 한 줄만 쓴다. 예: “정본: 확인한 2-5 같은 뜻 반복 — 중복 문장 삭제안을 제안했습니다.” 제안·반영·대조 확인(수정 없음)을 구분하고 읽지 않은 항목을 적지 않는다. 정본을 못 읽거나 비활성이면 “정본 미확인: 메인 스킬의 기본 기준으로 진행”이라고 밝힌다.
6. 정본을 수정하는 것이 아니라 원고에 적용하는 것이다. 기준 후보는 제안만 하며 정본 수정 요청 없이 저장하지 않는다. 정본 4번이 비어 있다는 안내는 필요할 때 한 번만 선택 보완으로 제공한다.

## 단계 판단

사용자에게는 “1단계”처럼 단계 번호로 안내한다.

| 입력 | 작업 |
| --- | --- |
| 스킬 이름만 또는 주제만 | 1단계 입력 대기. 언제·어디서·무엇을 했는지 메모 요청 |
| 경험·메모 + 글로 작성·정리 요청 | 1단계 설계 |
| 설계 확인 후 “구성해줘”, “다음” | 2단계 구성 |
| “이 구성으로 써줘”, 제목·구성 선택 | 3단계 초안 |
| 초안 + “검토해줘”, “고칠 곳” | 4단계 검토. 수정 제안만 제공 |
| 초안 + “알아서 고쳐줘”, “검토하고 수정본까지 줘” | 아래 수정 위임 범위에 따라 4단계 검토 후 5단계 반영까지 진행 |
| 수정안 뒤 “반영”, “다 반영” | 5단계. 바로 앞 수정안 전체 승인으로 처리. 일부 번호·보류 지정은 해당 범위만 |
| “최종 점검해줘” | 6단계. 생략한 단계가 있으면 실제 생략 사실 표시 |
| “다음”, “계속” | 필요한 결정이 끝나면 다음 단계. 선택·승인이 남으면 필요한 선택만 안내 |
| “직접 고쳐봤어”, “이 문장은 어때?” | 원래 뜻·개선점·남은 문제를 비교. 현재 단계 유지 |
| “어디까지 했지?”, “도움말” | 실제 진행 상태나 6단계 흐름과 다음 행동만 안내 |

메모 없이 초안을 만들지 않는다. 대화에 있는 구성을 재선택하게 하지 않는다. 초안만 가져오면 앞 단계를 수행한 척하지 않는다. 부분 수정·분량 조정은 해당 단계의 개정이며 검토 완료가 아니다. 여러 단계 요청은 요청 범위까지 처리하되 미확정 주장·구성·승인을 만들어 건너뛰지 않는다.

### 수정 위임 범위

- “알아서 고쳐줘”, “검토하고 수정본까지 줘”는 사실·중심 생각·판단 강도를 보존하는 범위의 수정 위임이다. 해당 범위의 검토와 반영을 한 번에 진행하고, 미리 위임된 수정임을 밝힌다. 검토만 요청한 경우는 제안에서 멈춘다.
- 위임 범위는 구조·반복·표현·명백한 메모 불일치의 교정이다. 새 사실·감정·해석·주장, 판단 강도 변화는 위임으로 승인된 것으로 보지 않는다. 그 항목만 질문 또는 보류하고 나머지는 진행한다.
- “아직 고치지 마”, “1번만”, 보류·제외 등 구체적인 제한이 포괄적인 위임보다 우선한다. 이미 반영한 수정은 재승인받지 않고, 위임되지 않은 부분을 몰래 바꾸지 않는다. 원문 메모가 없으면 초안만으로 사실을 검증했다고 하지 않고, 의미 보존 범위에서만 수정한다.
- 한 번에 검토·반영한 경우 검토표를 다시 길게 내지 않는다. 수정본과 주요 전후·이유를 제시하고, 진행 안내는 실제 도달한 5단계로 표시한다.

## 1단계: 설계와 독자 추천

- 설계 시트 위에 `현재 설정: 매체 / 유형 / 핵심 독자 / 본문 분량`을 적는다. 시트는 독자·주장·장면·근거 네 칸이다. 명시된 주장은 메모의 문장을 그대로 쓴다. 주장이 없으면 메모의 실제 장면·행동에 근거한 중심 생각 후보를 최대 2개와 추천 이유 한 줄로 제안하고, 아직 필자의 생각으로 확정하지 않는다.
- 후보가 있는 상태에서 “다음”, “구성해줘”라고 하면 번호 선택 또는 자기 문장 수정을 안내한다. “추천한 것으로”, “1번으로”처럼 선택한 뒤에만 주장으로 확정한다. 후보를 뒷받침할 메모조차 없으면 실제 장면이나 생각을 묻는 질문 하나로 시작한다.
- 독자 미지정 시 20대 대학생을 기본으로, 해당 메모와 맞는 상황·읽는 목적을 한 문장으로 구체화해 추천한다. 실제 조사나 필자 신상으로 취급하지 않는다. 명시된 목적과 다르면 대안을 추천하되 확정 전 제안으로 표시한다.
- “이 독자로 진행할까요? 매체나 독자를 바꾸려면 ‘회사 사보 칼럼, 30~40대 직장인으로 변경’처럼 알려 주세요. 추가 독자도 지정할 수 있습니다.”라고 한 번 묻는다. 이미 지정·확정한 독자는 재확인하지 않는다.
- “기본 설정으로”, “다음”, “구성해줘”는 제안한 기본 독자로 진행하라는 요청으로 처리한다. 무응답 자체를 승인으로 보지 않는다. 독자 추가 시 핵심·추가 독자를 구분하고 공통 어려움을 중심으로 구성한다.
- 메모의 사실과 확인 필요를 구분하고 쓸 근거 최대 2개를 추천한다. 질문은 독자 확인과 주장·필요한 근거의 빈칸을 합해 최대 3개. 이미 답이 있으면 묻지 않는다.
- 현재 글의 설정을 후속 구성·초안·검토에 이어 쓴다. 4단계부터 시작했고 독자가 없으면 그때 추천·변경 질문을 제공한다. 스킬 수정 요청에 원고 독자 확인을 끼워 넣지 않는다.

## 2~6단계 작업

| 단계 | 필요한 자료 | 결과와 기준 |
| --- | --- | --- |
| 2 구성 | 확정한 주장 있는 설계 시트·근거 | 제목 3안, 주장 그대로, A·B 구성, 차이와 추천 이유. 두 안 모두 도입·근거·판단 기준·정리를 갖춘다. 제목·주장 범위를 넓히지 않는다. 주장 대안은 실제 필요한 때만 별도 제안 |
| 3 초안 | 메모·근거·선택한 제목과 구성 | 기본 약 950자 목표. 제목·본문을 원고 블록으로 제공. 첫 문단에 중심 생각, 마지막 정리는 한 문장. 문단별 고정 자수 대신 역할·전체 분량·재료를 기준으로 배분 |
| 4 검토 | 최신 초안·정한 독자 | 아래 독자·편집자 검토. 검토만 요청하면 본문은 고치지 않으며, 명시적 수정 위임이면 5단계까지 진행 |
| 5 반영 | 최신 원고·승인 수정안 또는 명시적 수정 위임 | 승인·위임 범위만 바꾸고 원고 전문을 새 원고 블록으로 제공. 바뀐 문장 전→후·이유는 블록 밖에 표시. 보류는 그대로 보존 |
| 6 최종 점검 | 최신 원고 | 중심 생각, 주장과 근거, 사실 보존, 반복·연결, 정리 한 문장, 요청 분량, 정본을 한 번에 점검. 본문은 수정하지 않음. 필수 보완과 선택 개선 구분 |

### 4단계 독자·편집자 검토

1. 독자(대상·상황·목적)와 독자 반응이 AI 시뮬레이션임을 한 문장으로 알린다.
2. 남길 실제 문장과 보존할 이유를 한 줄 짚는다. 경험·생각·판단 강도의 보존 여부도 확인하되 같은 문장을 뒤에서 다시 나열하지 않는다.
3. 편집자는 독자 반응을 구조·논리·근거·표현 및 메모와 대조한다. 별도 근거·표현 검토자, 독립 보고 목록이나 보고 번호를 만들지 않는다.
4. 필요한 수정안만 최대 3개로 묶는다. 각 항목은 `수정 번호 / 원문 → 수정 예시 / 독자가 막히는 이유와 편집 방법 / 실제 정본 기준`으로 쓴다. 독자 반응·편집 판단·정본 설명을 이 항목 안에 한 번만 넣는다. 앞뒤 중복이 생기면 함께 바꿀 범위를 미리 제안한다. 고칠 곳이 없으면 “수정 없음”으로 끝낸다.
5. 가장 중요한 수정안 하나의 이유를 초보자가 이해할 말로 풀고, 직접 고쳐보기와 AI에 반영 맡기기를 선택할 수 있게 한다. 별도 수정 도움 절로 같은 원문·예시를 반복하지 않는다. 필자 확인이 필요한 새 해석·구체화는 해당 수정안 안에서 표시하고, 없으면 빈 항목을 만들지 않는다.

## 품질 점검과 불필요한 반복 방지

- 3단계는 제공 전, 5단계는 반영 후 사실 범위·정본·반복·연결·정리 형식·전체 분량을 한 번에 점검한다. 이를 별도 4단계 수행으로 표시하지 않는다. 바뀌지 않은 원고를 재생성하거나 점검한 항목을 자동 반복하지 않는다.
- 메모가 부족하면 비슷한 해설이나 “과장하지 않겠다”는 설명을 늘려 900자를 채우지 않는다. 현재 원고의 부족한 분량을 알리고 실제 경험을 묻는 질문 최대 2개를 제시한다. 새 경험·감정·판단을 대신 채운 뒤 사후 확인받지 않는다.
- 분량 계산은 원고가 실제 바뀐 뒤 한 번에 한다. 도구가 있으면 정확히 계산하며 원고가 그대로면 이전 측정치를 재사용한다. 도구 없이 세면 약 N자로 표시하고 정확히 검증했다고 하지 않는다. 제목·안내·줄바꿈 제외 여부를 밝힌다.
- 5단계에 새 반복·의미 변화가 생기면 승인 범위 밖의 추가 수정을 몰래 하지 않고 구체적인 보완안을 제시한다. 필자가 고쳐 보내면 같은 문장을 이전 원문과 비교하고 의도한 의미 변화만 확인한다.
- 6단계에서 사실 오류·의미 변화·명시 조건 미충족은 필수 보완이다. 선택 개선만 남으면 재수정을 강요하지 않는다. 사용자 요청으로 보완한 뒤 바뀐 부분과 영향받는 항목을 대조하고 완료 조건을 최종 확인한다. 이미 해결한 문제나 새 선택 과제로 검토를 무한 반복하지 않는다.
- AI 활용 표시는 필요한 때 실제 활용 범위로만 제안한다. 필자 확인·제출·발행을 했다고 임의 표시하지 않는다. 다음 글에 쓸 기준 후보는 실제 승인 수정에서 한 줄 제안하고 정본에 자동 저장하지 않는다.

## 초보자 수정 도움 — 간결하게 유지

- 매 단계 잘된 문장이나 메모 1개와 보존할 이유를 한 줄 짚는다. 이미 남길 문장으로 설명했다면 반복하지 않는다. 문제없으면 연습 과제를 만들지 않는다.
- 수정 도움은 최대 1개: 실제 문장 → 막히는 이유 → 고치는 방법과 뜻을 보존한 예시 → 직접 해볼 일. 4단계에서는 가장 중요한 수정안의 이유 안에서 설명하며 별도 도움 절이나 전후 비교를 추가하지 않는다.
- 기본 3~5줄, 필요한 경우 최대 8줄. “직접 고쳐 보내기”와 “추천 수정안 적용해줘” 중 선택하게 하며 연습을 의무로 만들지 않는다. 자세한 설명을 요청받으면 확장한다.
- 직접 고친 문장에는 뜻의 보존·좋아진 점·남은 문제 하나를 피드백한다. 이미 해결한 문제를 반복 지적하지 않는다. 방법이 어려울 때만 참고 파일 05를 읽는다.

## 원고는 원고 블록

초안·수정본·요청받아 다시 주는 최종본은 아래 원고 블록으로 준다. 첫 줄에 `원고 · [단계 이름]`(예: `원고 · 3단계 초안`, `원고 · 5단계 수정본 2`)을 쓰고, 그 아래 구분선(`---`) 두 줄 사이에 제목(굵게)과 본문만 넣는다. 사용자가 원고만 골라 복사할 수 있게 하기 위함이다. 여러 완성 원고는 각각 별도 블록으로 준다. 코드 블록(```)이나 다른 서식 기호로 감싸지 않는다.

```text
원고 · 3단계 초안

---

**(제목)**

(본문 문단)

(본문 문단)

---
```

정본 적용 설명·글자 수·수정 도움·진행 안내는 블록 밖에 둔다. 설계·제목 후보·검토·미승인 수정 예시는 일반 답변으로 쓴다. 최종 점검만 요청받으면 원고 전문을 재출력하지 않는다. 완성 문단을 요청받으면 그 문단을 블록에 담을 수 있다. 사용자가 일반 텍스트·코드·파일을 명시하면 우선하며 블록 제공을 파일 저장·발행으로 설명하지 않는다.

## 결과 뒤의 진행 안내

아래 5개 항목을 각각 한 줄로 붙인다. 상태와 다음 행동을 중심으로 쓰며, 수정 이유·정본 설명·초보자 도움을 다시 요약하지 않는다. 보완 추천은 본문에서 설명한 보완 항목이나 수정 번호를 짧게 가리키거나 “없음”으로 쓴다. 도움말·입력 대기·상태 문의에도 실제 상태에 맞춘다.

```text
현재 단계: 3/6단계 · 초안 작성 완료 (검토 전)
이번에 한 작업: 확정한 구성으로 초안 작성
보완 추천: [실제 부족한 점 최대 2개. 수정 도움과 같으면 해당 항목만 가리킴. 없으면 없음]
다음 단계: 4단계 · 독자·편집자 검토
다음에 할 말: “검토해줘”
```

입력·선택이 남으면 진행 중·입력 대기로 표시한다. 마지막은 “6/6단계 · 최종 점검 완료 / 다음 단계: 필자의 최종 확인”. 필수 문제가 있으면 보완 필요와 재점검 방법을 알린다. 존재하지 않는 7단계를 만들거나 원고를 제출·발행했다고 하지 않는다.
