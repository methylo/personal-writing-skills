# 02 단계별 출력 견본 (각 단계를 실행할 때 형식을 맞춘다)

이 파일은 형식이 불명확할 때 해당 단계 절만 읽는다. 매 단계 읽거나 이미 확인한 전체 견본을 다시 로딩하지 않는다. 메인 스킬의 간결한 출력 기준을 우선한다.

아래는 형식 견본이다. 내용은 수업용 가상 예시이며, 필자의 글에 옮겨 쓰지 않는다. 표와 목록의 모양과 번호 붙이는 법을 맞춘다. 아래의 기존 마지막 줄·다음 선택 안내는 SKILL.md의 공통 진행 안내로 대체한다. 단계 번호를 사용자에게 요구하지 않는다.

## 1단계 설계

```
현재 설정: 대학교 신문 / 칼럼 / 20대 대학생 / 본문 900~1,000자

설계 시트
독자(구체적인 추천)  읽거나 공부하려고 앉았지만 휴대폰 알림에 주의가 흐트러지는 20대 대학생. 행동을 돌아볼 질문을 찾는 독자.
주장  선택 대기. 메모에 근거한 후보 1~2개와 추천 이유를 아래에 제안한다.
장면  저녁, 책상에서 읽을 글을 펼쳤다가 휴대폰을 보고, 뒤집은 뒤 한 문단을 다시 읽었다.
근거  아래 근거 카드

독자 변경 질문
이대로 진행할까요? "기본 설정으로 진행"이라고 답하거나 "회사 사보 칼럼, 30~40대 직장인 독자로 변경"처럼 알려 주세요. 추가할 독자가 있다면 함께 알려 주세요. 이번 글의 변경값은 설계 시트에만 적용합니다.

빈칸 질문(이미 메모에 답이 있으면 다시 묻지 않는다)
1. 제안한 중심 생각 후보 중 하나를 고르거나 자기 문장으로 고쳐 주세요. 후보를 뒷받침할 메모가 부족하면 실제 생각 한 줄을 묻는다.
2. 외부 근거가 필요한 주장을 넣으려면 확인한 자료가 있나요? 경험 범위의 글에는 자료가 필수는 아닙니다.

근거 카드
확인한 사실  휴대폰을 뒤집은 뒤 한 문단을 다시 읽었다 (메모)
확인한 사실  집중이 완전히 좋아지지는 않았다 (메모)
확인 필요    없음. 집중력 향상 효과를 일반화하려면 외부 근거가 필요함

칼럼에 쓸 근거 2개 추천
1. 휴대폰을 뒤집은 뒤 한 문단을 다시 읽은 관찰
2. 집중이 완전히 좋아지지는 않았다는 한계

다음 선택: 빈칸에 답해 주세요.
```

## 2단계 구성

```
제목 3안
1. 결심보다 시작 장치를 바꾼다
2. 휴대폰을 뒤집는 것부터
3. 집중은 첫 문단에서 시작된다

주장 (시트 그대로)  결심보다 시작 장치를 바꾼다

A안  장면에서 주장으로
도입 / 근거 / 판단 기준 / 정리 (자리마다 한 줄)
B안  주장에서 장면으로
도입 / 근거 / 판단 기준 / 정리 (자리마다 한 줄)

차이: A안은 장면으로 독자를 끌어들이고, B안은 주장을 먼저 던진다.
다음 선택: 제목 하나와 A안·B안 중 하나를 골라 주세요.
```

## 3단계 초안

원고는 글쓰기 블록으로 제공한다. 아래 숫자는 형식 예시이며 실제 출력마다 고유 id를 쓴다.

:::writing{variant="standard" id="62147"}
(고른 제목)

(도입 약 200자)

(근거 약 350자)

(판단 기준 약 300자)

(정리 1문장)
:::

블록 밖 안내:
- 글자 수: 실제 도구로 계산한 값 또는 대략값을 구분한다.
- 없는 사실 여부와 적용한 정본 항목: 실제 결과를 적는다.
- 필요한 수정 도움과 공통 진행 안내를 이어 붙인다.

## 4단계 독자·편집자 검토

```text
독자: 휴대폰 알림에 읽기를 미루는 20대 대학생. 아래 반응은 AI 시뮬레이션입니다.
남길 문장: “집중이 완전히 좋아지지는 않았다.” — 메모의 한계와 판단 강도를 보존합니다.

수정 1
원문: “현대사회에서 집중력은 중요하다.”
→ 예시: “저녁에 책상에 앉아 읽을 글을 펼쳤다.”
이유·방법: 독자는 필자가 겪은 일을 알고 싶습니다. 누구에게나 해당하는 일반론 대신 메모의 장면으로 시작합니다. (정본 2-1)

수정 2
원문: “휴대폰을 내려놓자 집중력이 향상됐다.”
→ 예시: “휴대폰을 뒤집고 한 문단을 다시 읽었다.”
이유·방법: 행동과 결과가 메모와 다릅니다. 확인한 행동만 쓰고 효과를 단정하지 않습니다. (정본 2-4)

수정 3
원문: “삶을 바꾸는 소중한 깨달음을 얻었다.”
→ 예시: 삭제하고 앞뒤 연결 확인.
이유·방법: 경험보다 큰 상투적 결론입니다. 새 판단을 만들지 않고 삭제를 제안합니다. (정본 2-2·2-3)

직접 한 문장을 고쳐 보내거나 “수정 1만 반영해줘”라고 선택할 수 있습니다.
```

예시의 문제를 실제 원고에도 있다고 가정하지 않는다. 독자 반응·편집자 보고·정본 목록·수정 도움으로 같은 내용을 다시 나열하지 않는다. “알아서 고쳐줘”처럼 수정까지 위임받으면 메인 스킬의 위임 범위 안에서 5단계까지 진행하고, 수정본과 주요 전후·이유만 보여 준다. 보류·제외가 있으면 그 제한을 우선한다.

## 5단계 반영

:::writing{variant="standard" id="83496"}
(제목)

(승인한 수정을 반영한 원고 전문)
:::

블록 밖 안내:
- 바뀐 문장 목록: 수정 번호별 전 → 후 + 이유.
- 보류 항목: 실제로 남아 있는 항목만 표시.
- 정본 대조·주변 문장·분량 점검 결과.
- 필요한 수정 도움과 공통 진행 안내.

## 6단계 검수

```
제출 전 점검
1. 첫 3줄에 주장이 보인다 — 통과 (제목이 주장)
2. 주장의 크기가 근거를 넘지 않는다 — 통과
3. 메모와 필자 자료에 없는 사실이 없다 — 확인 필요 1개. 제출 전에 채우거나 그 문장을 빼세요.
4. 정리 문장이 제목의 주장과 맞는다 — 통과
5. 분량: 사용자 지정 범위, 미지정 시 900~1,000자 — 약 950자. 글자 수 기능으로 확인하세요.
6. AI 활용 표시 — 필요한 때 실제 활용 범위로만 제안. 예: “AI를 구성 제안과 독자·편집자 검토에 활용했다.” 필자 확인·제출·발행을 임의로 표시하지 않음

기준 후보 한 줄
정리 문장은 제목의 주장과 같은 뜻의 다른 말로 끝낸다.
정본에 넣을지는 필자가 정합니다.
```

## 모든 단계 뒤에 붙이는 진행 안내 예

4단계의 수정 도움은 수정안 이유에 통합한다. 다른 단계는 필요한 도움만 짧게 제공한 뒤, 아래 진행 안내 하나만 붙인다. 예시의 부족한 점은 실제 원고에서 확인한 경우에만 추천한다.

```text
현재 단계: 4/6단계 · 검토 완료 (수정 승인 대기)
이번에 한 작업: 정한 대학생 독자 관점에서 읽고, 편집자 관점에서 수정안 2개를 제안했습니다.
보완 추천: 수정 1의 반복 문장부터 줄일 것을 권합니다.
다음 단계: 5/6단계 · 승인한 수정 반영
다음에 할 말: “수정안 모두 반영해줘” 또는 “수정 1만 반영해줘”
```

최종 점검에서 남은 문제가 없으면 다음 단계는 필자의 최종 확인이다. 미해결 사항이 있으면 보완 필요 상태와 재점검 방법을 알린다.

## 정본 적용과 수정 도움

3~6단계 전에 SKILL.md의 정본 불러오기 규칙을 따른다. 정본을 읽지 못했으면 적용했다고 표시하지 않는다. 실제 항목 번호와 쉬운 설명을 함께 쓰며, 예시의 4 마무리 습관은 필자가 해당 기준을 채운 경우에만 적용한다.

단계별 수정 도움은 references/05-beginner-revision-guide.md를 따른다. 사용자에게 실제 문장을 고치는 방법과 선택 가능한 다음 행동을 안내하고, 기존 수정안·보완 추천을 길게 중복하지 않는다.

## 정본 연동을 설명하는 위치

- 작업 시작의 한 문장: 정본을 읽은 실제 상태와 이번 단계에서 대조할 기준을 안내한다. 아직 읽기 전이면 적용 예정으로만 알린다.
- 4단계는 각 수정안 이유에 실제 정본 기준을 함께 표시하고, 적용 목록을 별도로 반복하지 않는다. 3·5·6단계는 `정본: [실제 항목] — [제안·반영·대조한 일]` 한 줄로 쓴다.
- 예: "앞서 확인한 ‘내 글 정본’의 반복 기준으로 수정안을 검토하겠습니다."
- 결과 예: "정본: 2-5 같은 뜻 반복 — 승인한 중복 문장 삭제를 반영했습니다."
- 읽기에 실패하면 정본 미확인 상태를 알리고 메인 스킬의 기본 기준으로 진행했음을 표시한다. 확인·제안·반영의 상태를 섞지 않는다.
